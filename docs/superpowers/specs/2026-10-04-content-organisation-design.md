# Content Organisation Design

**Date:** 2026-10-04
**Status:** Approved
**Scope:** entity note layout under `games/<id>/entities/` and
`worlds/<id>/entities/`, `pkg/storage` (sync, index, migrations), `pkg/entity`,
`pkg/gui` (entity and folder routes), the Codex and Worlds studio entity lists
**Related:** `2026-10-04-content-editor-core-design.md`,
`2026-10-04-frontmatter-and-wikilink-intelligence-design.md`
**Feature branch:** `feat/content-authoring`

---

## 1. Problem

Every entity note is a flat file directly inside `entities/`. There is no way to
group a campaign's notes into places, factions, or acts, so a campaign with a
hundred notes is one undifferentiated list sorted by name. Concretely:

- `Service.ListEntities` (`pkg/gui/service.go:873`) and `Syncer.Sync`
  (`pkg/storage/sync.go:26`) both use a non-recursive `os.ReadDir` and skip
  directories, so a hand-made subfolder is invisible to the app.
- The entity id *is* the filename: `SaveEntity` overwrites `ent.ID = entityID`
  (`pkg/gui/service.go:979`), and `GetGraph` derives node ids from filenames
  (`pkg/gui/service.go:1159`). Adding folders without changing this would make
  identity positional, and moving a note would break every link to it.
- `rewriteInboundLinks` (`pkg/gui/service.go:1090`) exists to repair links after a
  merge, but it is a flat-directory scan and only runs on merge.

The organisation problem is therefore not "add a tree widget". It is "give a note
a location without letting the location become its identity".

## 2. Design

### 2.1 The model

An entity note lives at `<collection>/entities/**`, where `<collection>` is
`games/<id>` or `worlds/<id>`. Nesting is arbitrary. **Any directory under
`entities/` is a folder.** A folder has no file of its own: its directory name is
its label, and siblings sort case-insensitively.

The invariants that make this safe:

1. **`id` is the identity, and it is stable.** The frontmatter `id` names the
   note; the file's path is only where it happens to sit. Moving a note between
   folders changes no links, because nothing links by path.
2. **`id` is unique per collection.** This is already the database's rule
   (`entities.id TEXT PRIMARY KEY`, `pkg/storage/db.go:12`), and it is what the
   engine assumes: mentions, `MatchExistingEntity`, backlinks and the timeline all
   key on the id alone. Folders organise; they do not namespace.
3. **Frontmatter wins over the filename.** The `<id>.md` convention is kept
   because it makes the tree predictable, but a mismatch is tolerated rather than
   fatal. The loader records a `filename_mismatch` marker and the UI offers a
   one-click "rename file to match id" repair. This is the hand-edit tolerance
   `storage.Sync` already shows for malformed notes.
4. **Folders are organisational only.** The engine does not read them. The context
   assembler, scene scope, `MatchExistingEntity`, the working set and
   `history.jsonl` are untouched by this change.

### 2.2 Wikilinks

Link syntax does not change. `[[silver-hand]]` resolves by id anywhere in the
tree, which is the payoff of invariant 1: **a move rewrites nothing.**

One tolerance is added for hand-written links. `entity.WikilinkTarget`
(`pkg/entity/entity.go:161`) already unwraps `[[target|label]]`; resolution gains
a second pass so that a target which does not match an id is retried as its
basename. A note that writes `[[guilds/silver-hand]]` therefore still lands, and
the path-qualified form never needs to be generated by the app.

### 2.3 Storage and index

**Walk.** `Syncer.Sync` becomes a `filepath.WalkDir` walk over `entities/`. It
skips hidden directories (any segment beginning with `.`), non-`.md` files, and
the `assets/` directory, and it keeps today's behaviour of silently skipping a
note whose frontmatter will not parse.

**Column.** The `entities` table gains a `folder` column holding the note's
directory relative to `entities/`, normalised to forward slashes, with `''` for
the root. It is added as migration version 12 in `pkg/storage/migrate.go`
(`ALTER TABLE entities ADD COLUMN folder TEXT NOT NULL DEFAULT ''`), following the
existing ordered, idempotent migration shape.

```go
// Folder is where a note sits under entities/, relative and slash-separated, with
// "" for the root. It is a location, not frontmatter: two notes with the same
// body in different folders are the same note, so it must never be serialized.
```

**Entity.** `entity.Entity` gains a `Folder string` field. It is populated by the
loader and the writer and is deliberately **not** frontmatter:
`SerializeMarkdown` must not emit it and `frontmatter_json` must not carry it.
The store persists it in the new column.

**Readers.** `Service.ListEntities` (`pkg/gui/service.go:873`),
`Service.GetGraph` (`pkg/gui/service.go:1144`) and `Service.rewriteInboundLinks`
(`pkg/gui/service.go:1090`) walk recursively. `ListEntities` reports each note's
`Folder`; `GetGraph` keeps deriving node ids but from the parsed `id` rather than
the bare filename, so a nested note is a first-class node.

### 2.4 API surface

`EntitySummaryDTO` and `EntityDTO` (`pkg/gui/types.go`) gain `folder`. The entity
list stays a **flat array** with a folder on each item; the tree is a projection
the client builds. This keeps every existing consumer working and means an empty
folder is the only thing a flat list cannot express, which the folder routes below
cover.

Moving a note reuses the existing save route. `PUT /api/game/{id}/entity/{eid}`
accepts `folder` in the body; the service resolves the note's current location
from the store (falling back to a disk scan when the index is stale), writes the
new path, and removes the old file. Because the id is stable, no link rewrite
happens.

Folder routes, mounted in `pkg/gui/routes.go` and dispatched from `server.go`:

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/game/{id}/folders` | Folder tree (so empty folders are visible) |
| `POST` | `/api/game/{id}/folders` | Create `{path}` |
| `PUT` | `/api/game/{id}/folders` | Rename or move `{from, to}`, contents included |
| `DELETE` | `/api/game/{id}/folders` | Delete `?path=`; refuses a non-empty folder unless `recursive=true` |

The same four are mirrored at `/api/world/{id}/folders`. Every path in and out is
validated by one shared helper: relative, no `..` or `.` segment, no leading `/`,
no backslashes, no NUL, no segment beginning with `.`, each segment at most 64
characters. A rejected path is a `400`; nothing reaches the filesystem unchecked.

A save whose `id` collides with a different note returns `409` with a suggested
id, rather than silently overwriting a note in another folder.

### 2.5 UI surface

One shared `EntityTree` component, used by both studios:

- recursive folders with expand and collapse, and a filter box that searches
  names, ids and aliases inside every folder;
- drag-and-drop in both directions: a note onto a folder to file it, and onto the
  empty space below the tree to take it back out. A folder can be dragged into
  another, and never into itself;
- per-folder new subfolder, rename and delete; per-note move-to-folder. Rename
  reuses the move operation, because renaming a folder is a move to a new path in
  the same parent, so it needs no extra route;
- a delete confirmation that names the folder and counts the notes inside it,
  because the deletion is recursive;
- a note whose id disagrees with its filename is flagged from §2.1.

Every action is reachable without a pointer gesture as well as by dragging, and
the dialogs match the shape of the app's existing dialogs rather than the
browser's own prompt box.

Its first consumers are the flat entity list in `CodexDrawer`
(`frontend/src/components/CodexDrawer.tsx:261`) and the Templates tab in
`WorldsStudio` (`frontend/src/components/WorldsStudio.tsx:1016`). It is also the
navigation the editor-core spec builds on, which is why organisation lands first.

## 3. Migration and Compatibility

- **No forced migration.** Existing flat notes are root notes: the first recursive
  sync writes `folder = ''` for each and nothing moves on disk.
- The legacy `game.db` retirement in `storage.OpenGameStore` is unaffected; the
  new column is added to the campaign's `cache/index.db` by migration 12.
- `cache/index.db` stays disposable. A deleted or stale index is rebuilt from the
  Markdown, folder column included, by `EnsureIndexed`.
- A note that fails to parse keeps today's behaviour: skipped by sync, surfaced in
  the list with `parse_error` so it can be repaired rather than silently lost.

## 4. Non-Goals

- **Semantic folders.** A folder does not scope the engine, does not appear in the
  context prompt, and does not define a scene. The seam is deliberately left
  unbuilt; adding it later is a separate spec.
- **Folder metadata.** No `_folder.yaml`, no display names, no manual ordering, no
  per-folder icon or colour. The directory name is the label and order is
  alphabetical.
- **Folder notes.** A folder is not an entity and cannot be a wikilink target.
- **Nesting for systems or worlds.** Systems keep their fixed shape
  (`system.yaml`, `mechanics.js`, `prompts/`); worlds remain a top-level
  collection. Only the two entity trees nest.
- **Automatic link rewriting on move.** Not needed once identity is decoupled, and
  not wanted: it would rewrite files the user did not touch.

## 5. Success Criteria

- A note moved between folders keeps every `[[link]]` pointing at it, and no other
  file on disk is modified by the move.
- A campaign with hand-made nested folders shows that tree in the Codex after a
  resync, with empty folders visible.
- Two notes in different folders cannot share an id: the second save is rejected
  with a suggestion, not silently overwritten.
- A hand-written `[[guilds/silver-hand]]` resolves to the note with id
  `silver-hand`.
- Deleting `cache/index.db` and reopening the campaign reproduces the same tree
  and the same folder values.
- `go vet ./...` is clean and `go test ./...` passes.

## 6. Testing

- **`pkg/entity`** — `Folder` is not emitted by `SerializeMarkdown` and does not
  appear in the round-tripped frontmatter; `WikilinkTarget` basename tolerance.
- **`pkg/storage`** — recursive sync finds nested notes and records the right
  folder; hidden and non-`.md` entries are skipped; migration 12 is idempotent and
  a pre-existing flat campaign indexes with `folder = ''`; a deleted index is
  rebuilt identically.
- **`pkg/gui`** — folder create/rename/move/delete, including a non-empty folder
  delete refusing without `recursive=true`; path-traversal and hidden-segment
  rejection; entity move leaves links intact and removes the old file; duplicate
  id returns `409`; `ListEntities` and `GetGraph` include nested notes.
- **Frontend** — `npx tsc --noEmit` stays clean; the tree component's folder
  derivation from a flat entity list is covered by its pure helpers.
