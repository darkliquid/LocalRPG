# Roll Card Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A prominent pending-check card with Roll, Enter-a-roll, and Argue actions, streaming the adjudication through the existing turn processor.

**Architecture:** A `PendingCheckCard` component replaces the inline pending rendering; the Roll button calls IR-1's endpoint and feeds the stream through `TurnStreamProcessor`; two small DTO additions carry the actor values and resolved notation/bonuses.

**Tech Stack:** React 19 + Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-10-05-roll-card-design.md`
**Depends on:** IR-1, SYS-3.

## Global Constraints

- `noUnusedLocals`/`noUnusedParameters` are on.
- A campaign on the `auto` policy must render no pending card.
- The resolve-check stream is processed by the existing turn processor; do not add a second parser.
- Conventional Commits, subject under 72 chars.
